# 2026-09-13 — P0: bump Pico SDK to 2.3.0

Firmware **v0.1.3**. Branch `feature/unify-firmware-dsp`. First phase of the
onboard-DSP unification plan.

## What
- `firmware/CMakeLists.txt`: `sdkVersion` and `picotoolVersion` 2.2.0 → 2.3.0.
  Toolchain kept at `14_2_Rel1` (the only one installed here; SDK 2.3.0 builds
  fine with it — onboard_dsp nominally set 15_2_Rel1 but it isn't required).
- `.github/workflows/firmware.yml`: pico-sdk checkout `ref` 2.2.0 → 2.3.0.

## Why
The onboard-DSP merge needs SDK 2.3.0 (matches onboard_dsp; CMSIS-DSP setup).
Doing the bump first, in isolation, keeps the risky change separate.

## Verification
- All 4 variants build against `~/.pico-sdk/sdk/2.3.0` (confirmed via
  CMakeCache PICO_SDK_PATH). `version.h` = 0.1.3.
- Hardware: used the running v0.1.2 `reboot-dfu` to enter BOOTSEL, flashed
  `pic0rick-v0.1.3-rp2350-mux.uf2`, and confirmed over serial the board runs
  v0.1.3 (`board: pico2 (RP2350)`, SDK-2.3.0 build). Whole loop needed no
  button press.

## Notes
- SDK 2.3.0 emits `find_compiler` CMake *warnings* while probing toolchain
  triples before settling on `arm-none-eabi-gcc` — harmless.
